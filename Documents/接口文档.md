# Revo3 遥操接口文档

日常启停请参阅 [操作指令.md](操作指令.md)。字段结构以仓库中的 `.msg` 定义为准；本文补充 `.msg` 无法表达的语义，包括单位、缺省值、分流规则，以及失败时消费者可观察到的行为。

启动入口：`./scripts/teleop.sh [left|right|both] [blocks|unbox]`。默认启动双手模式，并使用 `blocks` 任务。切换任务前必须先停止驱动，再重新启动。

---

## 1. 运行环境

Ubuntu 22.04、ROS Humble、Python 3.10、conda `revo_retargeting`、x86_64。

```bash
git submodule update --init --recursive
./scripts/install_revo3_deps.sh
MANUS_SDK_ARCHIVE=/path/to/SDK.zip ./scripts/install_manus_sdk.sh
python -m colcon build --symlink-install --packages-select \
  manus_ros2_msgs manus_ros2 \
  revo3_mit_controller_msgs revo3_description revo3_mit_controller revo3_driver \
  manus_revo3_retarget
./scripts/check_system_deps.sh
```

`requirements.txt`：`numpy<2`，`empy==3.3.4`。apt 清单以 `scripts/install_revo3_deps.sh` 为准。

真机运行还需要执行 `./scripts/bind_revo3_ports.sh`、配置加密狗许可，并运行 `./scripts/calibrate_manus.sh`（详见操作指令）。

## 2. 契约类型与数据项

| 契约类型 | 数据项 | 定义文件 | 提供方 | 使用方 |
| --- | --- | --- | --- | --- |
| 消息 | `ManusGlove`（含 `ergonomics`、`raw_nodes`） | `src/manus_ros2_msgs/msg/ManusGlove.msg`（及 `ManusErgonomics.msg`、`ManusRawNode.msg`） | `manus_data_publisher` 或替代源 | retarget、录包、probe |
| 指令 | `Revo3MITCommand` | `src/brainco_revo3_ros2/revo3_mit_controller_msgs/msg/Revo3MITCommand.msg` | retarget 或自研发布者 | `joint_forward_mit_controller` |
| 关节 | 21 个 DoF 的名称与顺序 | `joint_names()`（`retarget_common.hpp`）与 URDF | 映射与驱动 | MIT、反馈对齐 |
| 配置 | 任务 overlay | `config/profiles/<task>.yaml` | 本仓库 | `pipeline_launch.py`、脚本白名单 |

如需修改字段、单位、关节顺序或话题名称，请先更新上表中的定义文件，再同步修改实现；不要只修改本文或 YAML 注释。

---

## 3. 数据流

```text
MANUS ~120 Hz  →  /manus_glove_{0,1}   ManusGlove
                      ↓ 按 `msg.side` 分流（不是话题下标）
                 retarget
                      ↓
                 …/retarget_targets    手套帧率
                      ↓  8 ms 线性插值
                 …/commands            200 Hz  →  MIT（超时约 0.25 s 后保持末位）
```

双手模式会启动两个进程：`manus_revo3_retarget_left` 和 `manus_revo3_retarget_right`。每个进程只控制一侧，但都会订阅两条手套话题。

以下控制器必须处于 **active** 状态：`revo3_joint_state`、`joint_forward_mit_controller`。请勿重复启动已经处于 active 状态的 MIT 控制器。

---

## 4. 关节序（MIT 指令）

每只手包含 21 个关节，顺序固定。`{side}` = `left` | `right`。屈曲角度越大，手指握拳程度越高；URDF 上限约为 85°。

| 下标 | 名字 |
| ---: | --- |
| 0–3 | `{side}_little_MPR/MCP/PIP/DIP_joint` |
| 4–7 | `{side}_ring_…` |
| 8–11 | `{side}_middle_…` |
| 12–15 | `{side}_index_…` |
| 16–20 | `{side}_thumb_MCP/PIP/DIP/CMP/CMR_joint` |

| 字段 | 单位 |
| --- | --- |
| `position` | rad |
| `velocity` | rad/s |
| `effort` | mA |
| 状态 `current` | A |

硬件端口：`/dev/revo3_hand_left` 对应从站 126（SN `BCUBL…`），`/dev/revo3_hand_right` 对应从站 127（SN `BCUBR…`）。

## 5. 消息语义

### `ManusGlove`（定义：`ManusGlove.msg`）

| 字段 | 必填 | 缺省或非法时的处理 |
| --- | --- | --- |
| `side` | 用于分流，必填 | 仅接受 `left`/`l` 或 `right`/`r`（大小写不敏感）。其他值会导致丢帧，不发送 MIT 指令 |
| `ergonomics[].type` | 四指和开合控制需要 | 缺少某个 type 时，对应关节角度按 **0°** 处理 |
| `ergonomics[].value` | 与 `type` 配套 | 单位为**度**，不是弧度 |
| `raw_nodes` | 拇指 IK 需要 | 缺少 `node_id` 0–24 的位置时，对应点按 0 处理，拇指姿态可能偏移 |

发布时，`ergonomics.type` 中的 `Left`/`Right` 前缀已移除：

- 屈曲：`Index/Middle/Ring/Pinky` × `MCPStretch` / `PIPStretch` / `DIPStretch`
- 开合：`IndexSpread` / `MiddleSpread` / `RingSpread` / `PinkySpread`
- 拇指：`ThumbMCPSpread` / `ThumbMCPStretch` / `ThumbPIPStretch` / `ThumbDIPStretch`

当前 retarget 不使用 `raw_sensor*` 或 `glove_id` 进行分流。

### `Revo3MITCommand`（定义：`Revo3MITCommand.msg`）

| 字段 | 规则 |
| --- | --- |
| `joint_names` | 为空时按控制器配置顺序处理；非空时按名称更新 |
| `position` / `velocity` / `effort` / `kp` / `kd` | 为空数组时保持控制器默认值；非空时长度必须与 `joint_names` 一致（`joint_names` 为空时按 21 个关节处理） |
| `kp`/`kd` YAML `< 0` | 回退至 `mit_default_*` |

Retarget 发布时始终带齐 21 个关节名称和 `position`。

## 6. 话题

`{side}` = `left` | `right`。默认命名空间为 `/revo3_{side}/`。QoS：Reliable、KeepLast 10。

| 话题 | 类型 | 频率 | 方向 |
| --- | --- | --- | --- |
| `/manus_glove_0`、`/manus_glove_1` | `ManusGlove` | ~120 Hz | 手套 → retarget |
| `…/retarget_targets` | `Revo3MITCommand` | 手套帧率 | 插值前 |
| `…/commands` | `Revo3MITCommand` | 200 Hz | 发给 MIT |
| `…/revo3_joint_state/joint_states` | `JointState` | 未固定 | 反馈（顺序不一定与 MIT 一致） |
| `…/dynamic_joint_states` | `DynamicJointState` | 未固定 | 包含电流 |

`/manus_glove_0` / `_1` 是发现顺序，不是左右。

## 7. 可观察失败与兼容

ROS 不提供 HTTP 状态码；消费者可通过以下现象判断状态：

| 现象 | 含义 |
| --- | --- |
| 手套有数据，但 MIT 没有新的 `commands` | `side` 与本进程不匹配，或数据帧被丢弃 |
| `commands` 停止更新约 0.25 s 以上 | MIT **保持末位**，不会自动回零 |
| 四指始终接近 0 | `ergonomics` 缺少 type，或单位被误写为弧度 |
| 启动时报 `empty list` / `tuple` | overlay 中写入了 `hold_*_fingers: []` |
| 两路进程同时占用 `/commands` | retarget 与自研发布者同时运行 |

兼容性约定：

- 向后兼容：新增可选 YAML 键、新任务 overlay，或未使用的 `ergonomics` type。
- 不兼容变更：修改关节顺序或名称、修改单位、修改 `side` 取值或话题路径，或改变已有字段的含义。

## 8. 对接

**仅发送 MIT 指令**

1. 确认驱动已启动，且 MIT 控制器处于 active 状态。
2. 向 `/revo3_{side}/joint_forward_mit_controller/commands` 发布 `Revo3MITCommand`。
3. 持续以至少 50 Hz 发布（遥操场景为 200 Hz）。
4. `position` 使用 rad，关节名称与第 4 节一致。
5. 执行 `./scripts/stop_revo3.sh teleop`，避免占用同一话题。

**仅替换手套数据源**

向 `/manus_glove_0` 或 `/manus_glove_1` 发布 `ManusGlove`，至少提供 `side` 和 `ergonomics`（单位为度）；拇指 IK 还需要 `raw_nodes`。

**运行时改参**

双手模式下，需分别对两个节点执行 `ros2 param set`；参数将在下一帧手套数据到达时生效。如需持久化，请将修改写回 YAML。

```bash
ros2 param set /manus_revo3_retarget_left mit_default_kp 2.0
ros2 param set /manus_revo3_retarget_right mit_default_kp 2.0
```

## 9. 任务 overlay

配置按以下顺序叠加，后者覆盖前者：`control.yaml` → 拇指 / 四指 / 开合 → `config/profiles/<task>.yaml` → Launch。

| 文件 | 覆盖什么 |
| --- | --- |
| `config/control.yaml` | 空挥 EMA、夹持门、闲指、默认 `kp/kd` |
| `config/profiles/blocks.yaml` | 闲指锁、夹持开、`kp/kd = 1.6/0.4` |
| `config/profiles/unbox.yaml` | 五指跟手、夹持关、`kp/kd = 2.8/0.6` |
| `config/four_finger_retarget.yaml` | `physical_*` 握拳/食指 |
| `config/spread_retarget.yaml` | 侧摆 offset |
| `config/thumb_retarget.yaml` | 拇指 |
| `profiles/unbox/revo3_controllers.yaml` 等 | 仅拆箱驱动启动位；换任务重启驱动 |

如需关闭闲置手指锁定，请使用 `hold_unused_fingers: false`，不要写 `hold_*_fingers: []`。

### 新增任务

对于多数场景，可将 `blocks.yaml` 复制为 `config/profiles/<task>.yaml`，并只填写需要覆盖的键：

```yaml
---
manus_revo3_retarget:
  ros__parameters:
    hold_unused_fingers: true
    hold_left_fingers: [little, ring, middle]
    hold_right_fingers: [little, ring, middle]
    pinch_soften_enabled: true
    mit_default_kp: 1.6
    mit_default_kd: 0.4
```

要通过 `./scripts/teleop.sh <task>` 启动，还需要在 `scripts/revo3_common.sh`、`teleop_revo3.sh` 和 `start_revo3_driver.sh` 中登记任务名称。未登记时，可使用 `task:=<task>` 或 `task_config:=/abs/path.yaml`。

如果启动位姿也需要改变，请参考 `unbox`，新增 `config/profiles/<task>/` 下的控制器配置和 `initial_positions_*.yaml`，并修改 `start_revo3_driver.sh`。驱动与 retarget 必须使用同一任务名称。

验收时执行 `./scripts/teleop.sh both <task>`，并确认日志中的 `task=` 与 `ros2 param get /manus_revo3_retarget_left mit_default_kp` 的结果均与 overlay 一致。
